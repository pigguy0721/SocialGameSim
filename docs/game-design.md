# ソシャゲ運営ローグライク — 統合ゲームデザイン仕様書

## 1. ゲームコンセプト

### 核心コンセプト
プレイヤーは借金をしてソシャゲを開発・リリースし、運営で借金を返済する経営シミュレーション×ローグライク。「借金完済」という明確なゴールを持ち、実在のソシャゲ事件・あるあるをモチーフにしたイベントが発生する。

### デザインの柱
1. **借金返済という明確な目標** — ゴールが分かりやすい
2. **2フェーズ制** — 開発期（リリース前）と運営期（リリース後）で異なる戦略
3. **ソシャゲあるあるを体験** — 「自分だったらこうするのに」を実現できる
4. **カイロソフト的な楽しさ** — 現実のパラメータを可視化して楽しむ

---

## 2. ゲームフロー

### フェーズ構成

```
【フェーズ1: 開発期（リリース前）】 約24ターン（2年間）
  借金で資金を調達 → ゲームの土台を作る
      ↓
【リリース判定】 ステータスが一定以上ならリリース可能
      ↓
【フェーズ2: 運営期（リリース後）】 借金返済＋サービス継続
  売上で借金を返しながらサ終を回避
      ↓
【エンディング】 借金完済 or サービス終了
```

### フェーズ1: 開発期

**期間**: 24ターン（2年間 = 1ターン1ヶ月）

**初期状態**:
- 借金: 3000万〜5000万円（検討中：選択式 or 固定）
- 資金: 借金額と同額
- 収入: なし（売上ゼロ）
- 支出: 毎ターン利子が発生

**目標**:
- リリースに必要なステータスを整える
- コンテンツ力、技術力、話題性を育てる
- 事前登録者数を増やす

**リリース判定**:
- 開発期終了時（24ターン目）に自動リリース
- 最低基準: コンテンツ力30以上 & 技術力20以上
  - 満たさない場合: 「低評価スタート」ペナルティ（初期ユーザー激減）
  - 満たす場合: 通常リリース
  - 高水準: ボーナス効果（初期ユーザー増加、話題性ブースト）

### フェーズ2: 運営期

**初期状態**:
- 開発期の最終ステータスを引き継ぐ
- ユーザー数: 事前登録者数 + リリースボーナス
- 借金残高: 開発期から継続（利子も継続）

**目標**:
- 借金完済（勝利条件）
- サービス終了の回避（ユーザー数・資金がゼロになると敗北）

**収支構造**:
- 売上: ユーザー数 × 課金圧 × 係数
- 支出: 維持費（ターン経過で増加）+ 利子
- 返済: 売上の一部が自動返済 or プレイヤーが返済額を選択（検討中）

## 3. ステータスシステム

### メインステータス（常時表示）

| パラメータ | 説明 | ゲームオーバー条件 | 変動要因 |
|---|---|---|---|
| **ユーザー数** | ゲームの利用者数 | ゼロで敗北 | 新規流入、離脱、話題性、コンテンツ力 |
| **資金** | 運営資金（万円単位） | ゼロで敗北 | 売上、維持費、カードコスト |
| **借金残高** | 返済すべき金額 | — | 利子で増加、返済で減少 |
| **コンテンツ力** | ゲーム内容の充実度 | — | コンテンツ系カードで増加 |
| **技術力** | サーバー・バグ対応力 | — | 技術系カードで増加、放置で減少 |
| **話題性** | 注目度・バズり度 | — | 広報活動、強制イベント、毎ターン自然減衰 |

### サブステータス（ツールチップ or 下部表示）

| パラメータ | 説明 | 範囲 | 変動要因 |
|---|---|---|---|
| **マンネリ度** | コンテンツの飽き | 0〜100 | 時間経過で上昇、新コンテンツで減少 |
| **ファン熱量** | コアファンの熱心さ | 0〜100 | コンテンツ力、炎上で激減 |
| **課金圧** | 課金の強さ | 0〜100 | 課金施策で上昇、高すぎると離脱率↑ |
| **開発チーム士気** | スタッフのやる気 | 0〜100 | 休養、ボーナス、トラブルで変動 |
| **バグ数** | 技術的負債 | 0〜∞ | 機能追加で増加、修正で減少 |

### 内部パラメータ（非表示）

- ユーザー離脱率
- 新規流入率
- 課金率
- セルランク（売上順位）

## 4. ターン進行システム

### ターン構成（1ターン = 1ヶ月）

```
1. ターン開始（月初）
   ↓
2. 【強制イベント判定】 — プラス/マイナスのイベントが発生
   ↓
3. 【収支計算】 — 売上・維持費・利子の計算（運営期のみ）
   ↓
4. 【ユーザー変動】 — 新規流入と離脱の計算
   ↓
5. 【話題性減衰】 — 話題性の自然減少
   ↓
6. 【カード選択】 — 3枚のカードから1つ選択 or 休養
   ↓
7. カード実行・結果表示
   ↓
8. ターン終了・次ターンへ
```

### 収支計算（運営期）

```
売上 = ユーザー数 × 課金圧 × 課金率係数
維持費 = 基本維持費 × (1 + ターン数 × 0.05)
利子 = 借金残高 × 利率（月次）
純利益 = 売上 - 維持費 - 利子
```

### ユーザー変動

```
新規流入 = 話題性 × 流入係数 × (ランダム 0.8〜1.2)
離脱数 = ユーザー数 × 離脱率
離脱率 = 基本離脱率 + マンネリ度補正 + 課金圧補正 + コンテンツ力補正
```

### 話題性減衰

```
話題性減少 = 現在の話題性 × 0.15 × (1 + 経過年数 × 0.1)
※ 時間が経つほど話題性が落ちやすくなる
```

## 5. カードシステム

### カードの基本仕様

- 毎ターン3枚のカードが提示される
- プレイヤーは1枚を選択して実行 or 休養を選択
- **カードは100%成功する**（失敗システムは廃止）
- **大成功判定あり**（関連ステータスが高いと効果1.5〜2倍）

### カードのコスト

- **資金コスト**: カード実行に必要な資金
- **体力コスト**: 開発チームの労力（士気と関連）
- カードによってはコストなしのものもある

### カードの種類

#### 開発期専用カード

| カード名 | 効果 | コスト |
|---|---|---|
| スタッフガチャ（10連） | スタッフ獲得（★1〜★3） | 資金大 |
| キャラデザイン制作 | コンテンツ力↑↑ | 資金、体力 |
| シナリオ執筆 | コンテンツ力↑↑↑ | 体力大 |
| サーバー基盤構築 | 技術力↑↑↑ | 資金大 |
| ティザーPV制作 | 話題性↑↑↑ | 資金 |
| 事前登録キャンペーン | 話題性↑↑、リリース時ユーザー↑ | 資金 |
| CBT実施 | 技術力↑、バグ数↓↓ | 資金、体力 |
| 追加融資 | 資金↑↑↑、借金↑↑↑ | 利子増加 |

#### 運営期カード

**コンテンツ系**:
- 新キャラ実装（コンテンツ力↑、話題性↑、資金↑）
- ストーリー更新（コンテンツ力↑↑↑、マンネリ↓↓）
- コラボイベント（ユーザー↑↑↑、話題性↑↑↑、コスト大）
- 復刻イベント（マンネリ↑、コスト極小）
- 高難易度コンテンツ追加（コア層のファン熱量↑）

**技術系**:
- バグ修正（技術力↑、バグ数↓）
- サーバー増強（技術力↑↑、サーバーダウン確率↓）
- UI/UXリニューアル（ユーザー離脱率↓）

**広報系**:
- SNS広報キャンペーン（話題性↑↑、ユーザー↑）
- インフルエンサー案件（話題性↑↑↑、ユーザー↑↑）
- 公式生放送（話題性↑↑、ファン熱量↑）
- テレビCM（話題性↑↑↑↑、コスト超大）

**課金施策系**:
- 限定キャラ実装（資金↑↑↑、課金圧↑↑、ファン熱量↓）
- 人権キャラ実装（資金↑↑↑↑、課金圧↑↑↑、ユーザー↓）
- 福袋販売（資金↑↑、ファン熱量↑）
- 石バラマキ（ファン熱量↑↑↑、資金↓）
- バトルパス導入（毎ターン安定収入↑、課金圧↑）
- 天井引き下げ（ファン熱量↑↑、資金微↓）

**トラブル対応系**（強制イベント後に出現）:
- 詫び石配布（ファン熱量回復、資金微↓）
- 公式謝罪声明（炎上沈静化）
- 緊急メンテ実施（技術力↑、バグ数↓）
- ロールバック（バグ被害帳消し、ユーザー↓）
- 返金対応（資金↓↓↓、ファン熱量↑）

### 休養

- カードを選ばず「休養」を選択可能
- 効果: 開発チーム士気↑↑、体力回復
- コスト: なし
- 注意: ターンを消費するため進捗が遅れる

## 6. 強制イベントシステム

### 基本仕様

- **カード選択とは別枠で発生**（カード枠を圧迫しない）
- 毎ターン30〜50%の確率で何かしらのイベントが発生
- ポジティブ/ネガティブの比率はステータスに依存
  - 好調時: ポジティブ 70% / ネガティブ 30%
  - 普通時: ポジティブ 50% / ネガティブ 50%
  - 不調時: ポジティブ 30% / ネガティブ 70%
- 同一イベントは最低3ターンのクールダウン

### イベント連鎖

特定のイベントは連鎖・派生する:

| 起点イベント | 派生イベント | 連鎖条件 |
|---|---|---|
| サーバーダウン | メンテ延長 | 技術力が低い |
| ガチャ確率誤表記 | 返金対応 or サイレント修正 | プレイヤー選択 |
| 公式SNS失言 | まとめサイトで叩かれる | 高確率で連鎖 |
| セルラン1位 | 記念石配布カード出現 | 次ターンのカード枠 |
| 限定キャラ実装 | セルラン1位 | 課金圧が高い時 |
| コラボイベント | 復帰ユーザー急増 | コラボ成功時 |

### 主要イベント例

**ポジティブ**:
- セルラン1位獲得（話題性↑↑↑、ユーザー↑↑）
- 有名配信者が実況（ユーザー↑↑↑、話題性↑↑）
- 二次創作爆増（ファン熱量↑↑↑、話題性↑↑）
- 攻略wiki充実（ユーザー離脱率↓）

**ネガティブ**:
- 緊急メンテナンス（そのターンのカード1枚減）
- ガチャ確率誤表記発覚（資金↓↓、話題性↓↓）
- 炎上（ファン熱量↓↓、話題性↓）
- 競合タイトル登場（ユーザー↓↓、話題性↓↓）
- 主要スタッフ退職（士気↓、スタッフ離脱）
- データ消失事故（ユーザー↓↓↓、資金↓↓、レア大災害）

詳細は `docs/events.md` を参照

## 8. 難易度設計

### 難易度上昇要素

1. **維持費の増加**: ターン経過で維持費が増加
   - 維持費 = 基本維持費 × (1 + ターン数 × 0.05)

2. **ユーザー離脱率の加速**: 時間経過でユーザーが離れやすくなる
   - 基本離脱率が年次で上昇

3. **話題性の減衰加速**: 経過年数で話題性の減衰が早くなる
   - 減衰係数 = 0.15 × (1 + 経過年数 × 0.1)

4. **マンネリ度の蓄積**: 同じようなカードを繰り返すとマンネリ度上昇
   - マンネリ度が高いとユーザー離脱率↑

5. **ネガティブイベント確率上昇**: 後半ほど災害イベントが発生しやすい
   - 競合タイトル登場などの確率上昇

6. **借金の利子**: 毎ターン発生し、借金残高に応じて増加

### バランス調整の方針

```
期待値の設計:
  序盤: 売上期待値 > 支出 → 比較的楽
  中盤: 売上期待値 ≒ 支出 → ギリギリの綱渡り
  終盤: 売上期待値 < 支出 → 戦略的な選択が必須
```

## 9. 勝利条件とエンディング

### 勝利条件

**借金完済** — 借金残高をゼロにする

### 敗北条件

以下のいずれかでゲームオーバー:
1. ユーザー数がゼロになる（サービス終了）
2. 資金がゼロになる（破産）

### エンディング

**通常エンディング**: 借金完済
- 生存期間に応じて評価ランク
  - 60ターン以上（5年）: 伝説の運営
  - 36ターン以上（3年）: 安定運営
  - 24ターン以上（2年）: まあまあ
  - 借金完済: 完済！

**真エンディング**: 借金完済 + ユーザー数50万人以上
- アニメ化決定イベント発生
- 特別なエンディング演出

**ゲームオーバー**:
- 生存期間に応じて評価
  - 12ターン未満: 即サ終
  - 12ターン以上: 短命

### 完済後

- ゲーム続行可能（フリーモード）
- 更なる目標: ユーザー数最大化、長期サービス継続など
