# ソシャゲ運営ローグライク — 統合ゲームデザイン仕様書

## 1. ゲームコンセプト

### 核心コンセプト
プレイヤーは借金をしてソシャゲを開発・リリースし、運営で借金を返済する経営シミュレーション×ローグライク。「借金完済」という明確なゴールを持ち、実在のソシャゲ事件・あるあるをモチーフにしたタスク/イベントが発生する。

### デザインの柱
1. **借金返済という明確な目標** — ゴールが分かりやすい
2. **2フェーズ制** — 開発期（リリース前）と運営期（リリース後）で異なる戦略
3. **タスク管理による運営感** — 月6件のタスクから優先順位を判断して対応
4. **スキル＋アイテムで成長** — ステータスに応じてスキルを習得、戦略の幅が広がる
5. **ソシャゲあるあるを体験** — 「自分だったらこうするのに」を実現できる

## 2. ゲームフロー

### フェーズ構成

```
【フェーズ1: 開発期（リリース前）】 約24ヶ月（2年間）
  借金で資金を調達 → ゲームの土台を作る
      ↓
【リリース判定】 ステータスが一定以上ならリリース可能
      ↓
【フェーズ2: 運営期（リリース後）】 借金返済＋サービス継続
  売上で借金を返しながらサ終を回避
      ↓
【エンディング】 借金完済 or サービス終了
```

### フェーズ1: 開発期

**期間**: 24ヶ月（2年間 = 1ヶ月4週 = 96行動）

**初期状態**:
- 借金: 3000万〜5000万円（固定 or 選択式）
- 資金: 借金額と同額
- 収入: なし（売上ゼロ）
- 支出: 毎月利子が発生

**目標**:
- リリースに必要なステータスを整える
- 技術力、知名度、コンテンツ力を育てる
- 事前登録者数を増やす

**リリース判定**:
- 開発期終了時（24ヶ月目）に自動リリース
- 最低基準: 技術力30以上 & コンテンツ力30以上
  - 満たさない場合: 「低評価スタート」ペナルティ（初期ユーザー激減）
  - 満たす場合: 通常リリース
  - 高水準（各50以上）: ボーナス効果（初期ユーザー増加、知名度ブースト）

### フェーズ2: 運営期

**初期状態**:
- 開発期の最終ステータスを引き継ぐ
- ユーザー数: 事前登録者数 + リリースボーナス
- 借金残高: 開発期から継続（利子も継続）

**目標**:
- 借金完済（勝利条件）
- サービス終了の回避（ユーザー数・資金がゼロになると敗北）

**収支構造**:
- 売上: ユーザー数 × 課金率 × 基本課金単価
- 支出: 維持費（月経過で増加）+ 利子
- 返済: 売上の一部が自動返済

## 3. ステータスシステム

### 基本情報（ゲーム進行に必須）

| パラメータ | 説明 | ゲームオーバー条件 |
|---|---|---|
| **ユーザー数** | ゲームの利用者数 | ゼロで敗北 |
| **資金** | 運営資金（万円単位） | ゼロで敗北 |
| **借金残高** | 返済すべき金額 | 完済で勝利 |

### メインステータス（3つのみ）

ゲームの品質を表す3つのパラメータ。すべてのスキル効果とタスク結果はこれらに集約される。

| パラメータ | 説明 | 効果 | 変動要因 |
|---|---|---|---|
| **技術力** | サーバー・バグ対応力 | 高いとトラブル発生率↓、ユーザー離脱率↓ | 技術系スキルで増加、放置で減少 |
| **知名度** | 世間の注目度・認知度 | 高いと新規ユーザー流入↑、毎月自然減衰 | 広報活動、タスク対応で変動 |
| **コンテンツ力** | ゲーム内容の充実度 | 高いとユーザー満足度↑、課金率↑ | コンテンツ系スキルで増加 |

### パラメータの範囲

- 各ステータス: 0〜100
- ユーザー数: 0〜999,999
- 資金: マイナス不可（ゼロで敗北）
- 借金残高: ゼロで勝利

### 派生指標（画面に表示）

メインステータスから自動計算され、プレイヤーに表示される指標：

| 指標 | 算出方法 | 表示形式 | 効果 |
|---|---|---|---|
| **アプリストア評価** | (技術力 + コンテンツ力) / 2 を★に変換 | ★1〜★5 | 高いと新規流入↑、低いとユーザー離脱↑ |
| **セルランク** | 売上額から順位を算出 | 1位〜圏外 | 高順位で知名度↑、1位でイベント発生 |

**アプリストア評価の計算**:
```
評価スコア = (技術力 + コンテンツ力) / 2
★5: 評価スコア 80以上
★4: 評価スコア 60〜79
★3: 評価スコア 40〜59
★2: 評価スコア 20〜39
★1: 評価スコア 0〜19
```

**セルランクの計算**:
```
月間売上に応じて順位を決定（他の仮想タイトルとの競争をシミュレート）
1位〜10位: 超ヒット（知名度+15/月）
11位〜50位: ヒット（知名度+10/月）
51位〜100位: 中堅（知名度+5/月）
101位以降: 低迷（知名度変化なし）
圏外: 不人気（知名度-5/月）
```

### 内部計算に使われる要素（非表示）

以下は画面に表示されないが、内部計算で使用：
- ユーザー離脱率（コンテンツ力、技術力、アプリストア評価から算出）
- 新規流入率（知名度、アプリストア評価から算出）
- 課金率（コンテンツ力から算出）
- トラブル発生確率（技術力から算出）

## 4. ターン進行システム

### 時間単位

**1ヶ月 = 4週 = 4回行動**

- プレイヤーは月に4回行動できる（週1回ペース）
- 各行動で「スキル使用」「アイテム使用」「休養」のいずれかを選択

### 月の構成（1ヶ月 = 4週）

```
【月初（第1週開始前）】
  ↓
1. タスク発生（6件程度ランダム生成、ポジティブ/ネガティブ混在）
  ↓
2. 収支計算（運営期のみ：売上・維持費・利子）
  ↓
3. ユーザー変動（新規流入・離脱）
  ↓
4. 知名度減衰
  ↓
5. セルランク更新
  ↓
【第1週開始】
  ↓
プレイヤー行動（スキル/アイテム/休養）
  ↓
【第2週】
  ↓
プレイヤー行動
  ↓
【第3週】
  ↓
プレイヤー行動
  ↓
【第4週】
  ↓
プレイヤー行動
  ↓
【月末処理】
- 放置されたネガティブタスクの悪化判定
- 悪化したタスクの効果適用（ステータス低下など）
- 確率的な新規タスク誘発（例：バグ放置→30%で炎上タスク発生）
- 未対応のポジティブタスクは消滅（機会損失）
  ↓
次の月へ
```

### 収支計算（運営期のみ、月初）

```
課金率 = f(コンテンツ力)  // コンテンツ力が高いほど課金率が上がる
売上 = ユーザー数 × 課金率 × 基本課金単価
維持費 = 基本維持費 × (1 + 月数 × 0.05)
利子 = 借金残高 × 利率（月次）
純利益 = 売上 - 維持費 - 利子
自動返済 = max(0, 純利益 × 0.3)  // 黒字の30%を自動返済
```

### ユーザー変動（月初）

```
新規流入率 = f(知名度)  // 知名度が高いほど新規流入が増える
新規流入 = 新規流入率 × 流入係数 × (ランダム 0.8〜1.2)

離脱率 = 基本離脱率 - f(コンテンツ力) - f(技術力)  // 2つのパラメータが高いと離脱率が下がる
離脱数 = ユーザー数 × 離脱率
```

### 知名度減衰（月初）

```
知名度減少 = 現在の知名度 × 0.15 × (1 + 経過年数 × 0.1)
※ 時間が経つほど知名度が落ちやすくなる
※ 広報活動やタスク対応で知名度を維持・向上させる必要がある
```

## 5. タスクシステム

### 基本仕様

- **月初に6件程度のタスクがランダム発生**（ポジティブ/ネガティブ混在）
- **タスクは右側の常時表示エリアに一覧表示**
- **ネガティブタスクは月末に悪化判定**（放置で悪化）
- **ポジティブタスクは月末に消滅**（未対応なら機会損失）
- **タスクは月をまたいで持ち越す**（ネガティブのみ、ポジティブは消える）
- **プレイヤーは4回の行動で対応するタスクを選択**（全部やる必要なし）

### タスクの種類

#### ネガティブタスク（放置で悪化）

| カテゴリ | タスク例 | 対応スキル | 放置時の悪化（月末） | 誘発確率 |
|---|---|---|---|---|
| **技術トラブル** | バグ報告 | バグ修正 | 技術力-5、30%で「大規模バグ」誘発 | — |
| **技術トラブル** | 大規模バグ発生 | 緊急メンテ | 技術力-15、ユーザー-500、50%で「炎上」誘発 | バグ報告放置30% |
| **技術トラブル** | サーバー負荷増大 | サーバー増強 | 技術力-10、ユーザー-300、40%で「サーバーダウン」誘発 | — |
| **技術トラブル** | サーバーダウン | 緊急メンテ | 技術力-20、ユーザー-1000、知名度-15 | サーバー負荷放置40% |
| **コンテンツ枯渇** | 新キャラ要望 | キャラ企画 | コンテンツ力-5 | — |
| **コンテンツ枯渇** | イベント枯渇 | イベント企画 | コンテンツ力-10、ユーザー-200 | — |
| **炎上対応** | ユーザークレーム | 公式声明 | 知名度-5、30%で「SNS炎上」誘発 | — |
| **炎上対応** | SNS炎上 | 詫び石配布 | 知名度-15、ユーザー-800、50%で「大炎上」誘発 | クレーム放置30% or バグ放置50% |
| **炎上対応** | 大炎上 | 返金対応 | 知名度-30、ユーザー-2000、資金-500万 | SNS炎上放置50% |

#### ポジティブタスク（対応で報酬、放置で消滅）

| カテゴリ | タスク例 | 対応スキル | 報酬 | 放置時 |
|---|---|---|---|---|
| **広報機会** | CM出稿依頼 | SNS広報 or テレビCM | 知名度+15、ユーザー+500 | 機会損失（月末消滅） |
| **広報機会** | コラボ打診 | コラボ交渉 | 知名度+25、ユーザー+1500、コンテンツ力+10 | 機会損失（月末消滅） |
| **広報機会** | インフルエンサー案件 | インフル案件 | 知名度+20、ユーザー+800 | 機会損失（月末消滅） |
| **季節イベント** | 水着イベント準備 | イベント企画 | コンテンツ力+10、知名度+10、資金+300万 | 機会損失（月末消滅） |
| **季節イベント** | 周年記念準備 | 大型イベント企画 | コンテンツ力+20、知名度+20、ユーザー+2000 | 機会損失（月末消滅） |
| **投資機会** | 広告費増額提案 | 資金使用 | 知名度+25 | 機会損失（月末消滅） |
| **投資機会** | 開発費増額提案 | 資金使用 | コンテンツ力+15、技術力+15 | 機会損失（月末消滅） |

### タスクの表示

各タスクには視覚的な種別・優先度が表示される：

| 種別 | 表示 | 意味 |
|---|---|---|
| 🔴 ネガティブ（緊急） | 赤色 | 即対応しないと大ダメージ、誘発リスク高 |
| 🟡 ネガティブ（重要） | 黄色 | 放置で悪化、誘発リスク中 |
| 🟢 ポジティブ（機会） | 緑色 | 対応で報酬、月末に消滅 |
| 🔵 ポジティブ（大機会） | 青色 | 対応で大報酬、月末に消滅 |

### タスクの悪化システム（月末処理）

**ネガティブタスクのみ**が月末に悪化判定される：

```
月初: タスク発生（悪化度0）
  ↓
月中: プレイヤーが4回行動
  ↓
月末: 未対応のネガティブタスクを判定
  ↓
- 悪化度+1（悪化度0→1→2→3...）
- 悪化度に応じたペナルティ適用
  - 悪化度1: 効果小（例：技術力-5）
  - 悪化度2: 効果中（例：技術力-10、ユーザー-100）
  - 悪化度3: 効果大（例：技術力-20、ユーザー-500、知名度-10）
  - 悪化度4以降: 最大ペナルティ維持
- 確率的に新規タスク誘発判定
  ↓
次月へ持ち越し
```

**ポジティブタスク**は月末に消滅：
```
月初: タスク発生
  ↓
月中: プレイヤーが対応すれば報酬獲得＆タスク消滅
  ↓
月末: 未対応なら消滅（機会損失）
```

### 確率的なタスク誘発システム

月末の悪化判定時、**確率的に新規タスクが誘発**される：

| トリガータスク | 条件 | 誘発タスク | 確率 |
|---|---|---|---|
| バグ報告 | 放置（悪化度1以上） | 大規模バグ発生 | 30% |
| 大規模バグ発生 | 放置（悪化度1以上） | SNS炎上 | 50% |
| サーバー負荷増大 | 放置（悪化度1以上） | サーバーダウン | 40% |
| ユーザークレーム | 放置（悪化度1以上） | SNS炎上 | 30% |
| SNS炎上 | 放置（悪化度1以上） | 大炎上 | 50% |
| イベント枯渇 | 放置（悪化度2以上） | ユーザークレーム | 40% |

### タスクの解決

- **対応するスキルを使用**でタスク解決
- スキル効果でステータス上昇＋タスク消滅
- ポジティブタスクは報酬も獲得

## 6. スキルシステム

### スキル習得方法

**ステータスが一定値に達すると自動習得**

| ステータス条件 | 習得スキル | カテゴリ | 効果 |
|---|---|---|---|
| 技術力 20 | バグ修正 | 技術 | バグ報告タスク解決、技術力+10 |
| 技術力 40 | サーバー増強 | 技術 | サーバー負荷タスク解決、技術力+15 |
| 技術力 60 | UI/UX改善 | 技術 | 技術力+20、知名度+10 |
| 知名度 20 | SNS広報 | 広報 | 知名度+10 |
| 知名度 40 | インフルエンサー案件 | 広報 | 知名度+20、ユーザー+500 |
| 知名度 60 | テレビCM | 広報 | 知名度+30、ユーザー+2000 |
| コンテンツ力 20 | キャラクター企画 | コンテンツ | 新キャラタスク解決、コンテンツ力+10 |
| コンテンツ力 40 | イベント企画 | コンテンツ | イベント系タスク解決、コンテンツ力+15 |
| コンテンツ力 60 | 大型イベント企画 | コンテンツ | 周年記念タスク解決、コンテンツ力+20、知名度+15 |
| 複合（技30知30） | コラボ交渉 | 複合 | コラボタスク解決、全ステータス+10、ユーザー+1000 |
| 複合（技20コ20） | 緊急メンテ | 複合 | 緊急タスク解決、技術力+15 |

### スキルの使用

- **1回の行動で1スキル使用可能**
- **資金コストが必要**（スキルによって異なる）
- **タスクに対応するスキル**を使うとタスクが解決
- **タスクに無関係なスキル**を使うと単純にステータスが上昇

## 8. 強制イベントシステム

### 基本仕様

- **タスクとは別枠で発生**
- **月初に30%の確率でランダム発生**
- **プレイヤーの選択不要、自動で効果適用**
- **ポジティブ/ネガティブの比率はステータスに依存**

### 主要イベント例

**ポジティブ**:
- セルラン1位獲得（知名度+30、ユーザー+2000）
- 有名配信者が実況（ユーザー+3000、知名度+20）
- 二次創作爆増（コンテンツ力+20、知名度+15）
- アプリストアでフィーチャー（知名度+25、ユーザー+2500）

**ネガティブ**:
- 競合タイトル登場（ユーザー-1000、知名度-10）
- データ消失事故（ユーザー-3000、資金-500万、技術力-20、緊急タスク発生）

## 9. UI/UX設計

## 11. 難易度設計

### 難易度上昇要素

1. **維持費の増加**: 月経過で維持費が増加
   - 維持費 = 基本維持費 × (1 + 月数 × 0.05)

2. **ユーザー離脱率の加速**: 時間経過でユーザーが離れやすくなる
   - 基本離脱率が年次で上昇

3. **知名度の減衰加速**: 経過年数で知名度の減衰が早くなる
   - 減衰係数 = 0.15 × (1 + 経過年数 × 0.1)

4. **コンテンツの陳腐化**: 時間経過でコンテンツ力が自然減衰
   - 常に新しいコンテンツを投入し続ける必要がある

5. **タスク発生数の増加**: 後半ほどタスクが多く発生
   - 初期: 月4〜6件 → 後半: 月6〜8件

6. **借金の利子**: 毎月発生し、借金残高に応じて増加

### バランス調整の方針

```
期待値の設計:
  序盤: タスク対応余裕あり、売上 > 支出
  中盤: タスク対応ギリギリ、売上 ≒ 支出
  終盤: タスク取捨選択必須、売上 < 支出（スキル・アイテム活用が鍵）
```

## 12. 勝利条件とエンディング

### 勝利条件

**借金完済** — 借金残高をゼロにする

### 敗北条件

以下のいずれかでゲームオーバー:
1. ユーザー数がゼロになる（サービス終了）
2. 資金がゼロになる（破産）

### エンディング

**通常エンディング**: 借金完済
- 生存期間に応じて評価ランク
  - 60ヶ月以上（5年）: 伝説の運営
  - 36ヶ月以上（3年）: 安定運営
  - 24ヶ月以上（2年）: まあまあ

**真エンディング**: 借金完済 + ユーザー数50万人以上
- アニメ化決定イベント発生
- 特別なエンディング演出

**ゲームオーバー**:
- 生存期間に応じて評価
  - 12ヶ月未満: 即サ終
  - 12ヶ月以上: 短命
