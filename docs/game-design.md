# ソシャゲ運営ローグライク — 統合ゲームデザイン仕様書

## 1. ゲームコンセプト

### 核心コンセプト
プレイヤーは借金をしてソシャゲを開発・リリースし、運営で借金を返済する経営シミュレーション×ローグライク。「借金完済」という明確なゴールを持ち、実在のソシャゲ事件・あるあるをモチーフにしたイベントが発生する。

### デザインの柱
1. **借金返済という明確な目標** — ゴールが分かりやすい
2. **2フェーズ制** — 開発期（リリース前）と運営期（リリース後）で異なる戦略
3. **ソシャゲあるあるを体験** — 「自分だったらこうするのに」を実現できる
4. **カイロソフト的な楽しさ** — 現実のパラメータを可視化して楽しむ

## 2. ゲームフロー

### フェーズ構成

```
【フェーズ1: 開発期（リリース前）】 約24ターン（2年間）
  借金で資金を調達 → ゲームの土台を作る
      ↓
【リリース判定】 ステータスが一定以上ならリリース可能
      ↓
【フェーズ2: 運営期（リリース後）】 借金返済＋サービス継続
  売上で借金を返しながらサ終を回避
      ↓
【エンディング】 借金完済 or サービス終了
```

### フェーズ1: 開発期

**期間**: 24ターン（2年間 = 1ターン1ヶ月）

**初期状態**:
- 借金: 3000万〜5000万円（検討中：選択式 or 固定）
- 資金: 借金額と同額
- 収入: なし（売上ゼロ）
- 支出: 毎ターン利子が発生

**目標**:
- リリースに必要なステータスを整える
- コンテンツ力、技術力、話題性を育てる
- 事前登録者数を増やす

**リリース判定**:
- 開発期終了時（24ターン目）に自動リリース
- 最低基準: コンテンツ力30以上 & 技術力20以上
  - 満たさない場合: 「低評価スタート」ペナルティ（初期ユーザー激減）
  - 満たす場合: 通常リリース
  - 高水準: ボーナス効果（初期ユーザー増加、話題性ブースト）

### フェーズ2: 運営期

**初期状態**:
- 開発期の最終ステータスを引き継ぐ
- ユーザー数: 事前登録者数 + リリースボーナス
- 借金残高: 開発期から継続（利子も継続）

**目標**:
- 借金完済（勝利条件）
- サービス終了の回避（ユーザー数・資金がゼロになると敗北）

**収支構造**:
- 売上: ユーザー数 × 課金圧 × 係数
- 支出: 維持費（ターン経過で増加）+ 利子
- 返済: 売上の一部が自動返済 or プレイヤーが返済額を選択（検討中）

## 3. ステータスシステム

### 基本情報（ゲーム進行に必須）

| パラメータ | 説明 | ゲームオーバー条件 |
|---|---|---|
| **ユーザー数** | ゲームの利用者数 | ゼロで敗北 |
| **資金** | 運営資金（万円単位） | ゼロで敗北 |
| **借金残高** | 返済すべき金額 | 完済で勝利 |

### メインステータス（3つのみ）

ゲームの品質を表す3つのパラメータ。すべてのカード効果とイベントはこれらに集約される。

| パラメータ | 説明 | 効果 | 変動要因 |
|---|---|---|---|
| **技術力** | サーバー・バグ対応力 | 高いとトラブル発生率↓、ユーザー離脱率↓ | 技術系カードで増加、放置で減少 |
| **知名度** | 世間の注目度・認知度 | 高いと新規ユーザー流入↑、毎ターン自然減衰 | 広報活動、強制イベントで変動 |
| **コンテンツ力** | ゲーム内容の充実度 | 高いとユーザー満足度↑、課金率↑ | コンテンツ系カードで増加 |

### パラメータの範囲

- 各ステータス: 0〜100
- ユーザー数: 0〜999,999
- 資金: マイナス不可（ゼロで敗北）
- 借金残高: ゼロで勝利

### 内部計算に使われる要素（非表示）

以下は画面に表示されないが、内部計算で使用：
- ユーザー離脱率（コンテンツ力、技術力から算出）
- 新規流入率（知名度から算出）
- 課金率（コンテンツ力から算出）
- トラブル発生確率（技術力から算出）

## 4. ターン進行システム

### ターン構成（1ターン = 1ヶ月）

```
1. ターン開始（月初）
   ↓
2. 【強制イベント判定】 — プラス/マイナスのイベントが発生
   ↓
3. 【収支計算】 — 売上・維持費・利子の計算（運営期のみ）
   ↓
4. 【ユーザー変動】 — 新規流入と離脱の計算
   ↓
5. 【知名度減衰】 — 知名度の自然減少
   ↓
6. 【カード選択】 — 3枚のカードから1つ選択 or 休養
   ↓
7. カード実行・結果表示
   ↓
8. ターン終了・次ターンへ
```

### 収支計算（運営期）

```
課金率 = f(コンテンツ力)  // コンテンツ力が高いほど課金率が上がる
売上 = ユーザー数 × 課金率 × 基本課金単価
維持費 = 基本維持費 × (1 + ターン数 × 0.05)
利子 = 借金残高 × 利率（月次）
純利益 = 売上 - 維持費 - 利子
```

### ユーザー変動

```
新規流入率 = f(知名度)  // 知名度が高いほど新規流入が増える
新規流入 = 新規流入率 × 流入係数 × (ランダム 0.8〜1.2)

離脱率 = 基本離脱率 - f(コンテンツ力) - f(技術力)  // 2つのパラメータが高いと離脱率が下がる
離脱数 = ユーザー数 × 離脱率
```

### 知名度減衰

```
知名度減少 = 現在の知名度 × 0.15 × (1 + 経過年数 × 0.1)
※ 時間が経つほど知名度が落ちやすくなる
※ 広報活動やイベントで知名度を維持・向上させる必要がある
```

## 5. カードシステム

### カードの基本仕様

- 毎ターン3枚のカードが提示される
- プレイヤーは1枚を選択して実行 or 休養を選択
- **カードは100%成功する**（失敗システムは廃止）
- **大成功判定あり**（関連ステータスが高いと効果1.5〜2倍）

### カードのコスト

- **資金コスト**: カード実行に必要な資金
- カードによってはコストなしのものもある

### カードの種類（3つのカテゴリ）

すべてのカードは以下の3つのカテゴリに分類される：

#### 開発期専用カード

| カテゴリ | カード例 | 効果 | コスト |
|---|---|---|---|
| **技術** | サーバー基盤構築 | 技術力↑↑↑ | 資金大 |
| **技術** | CBT実施 | 技術力↑↑ | 資金中 |
| **知名度** | ティザーPV制作 | 知名度↑↑↑ | 資金中 |
| **知名度** | 事前登録キャンペーン | 知名度↑↑、リリース時ユーザー↑ | 資金中 |
| **コンテンツ** | キャラデザイン制作 | コンテンツ力↑↑ | 資金中 |
| **コンテンツ** | シナリオ執筆 | コンテンツ力↑↑↑ | 資金小 |
| **特殊** | 追加融資 | 資金↑↑↑、借金↑↑↑ | なし |

#### 運営期カード

| カテゴリ | カード例 | 効果 | コスト |
|---|---|---|---|
| **技術** | バグ修正 | 技術力↑↑ | 資金小 |
| **技術** | サーバー増強 | 技術力↑↑↑ | 資金大 |
| **技術** | UI/UXリニューアル | 技術力↑、知名度↑ | 資金中 |
| **知名度** | SNS広報キャンペーン | 知名度↑↑ | 資金小 |
| **知名度** | インフルエンサー案件 | 知名度↑↑↑、ユーザー↑↑ | 資金大 |
| **知名度** | 公式生放送 | 知名度↑↑ | 資金小 |
| **知名度** | テレビCM | 知名度↑↑↑↑ | 資金超大 |
| **コンテンツ** | 新キャラ実装 | コンテンツ力↑↑、知名度↑、資金↑ | 資金中 |
| **コンテンツ** | ストーリー更新 | コンテンツ力↑↑↑ | 資金小 |
| **コンテンツ** | コラボイベント | コンテンツ力↑↑、知名度↑↑↑、ユーザー↑↑↑ | 資金超大 |
| **コンテンツ** | 復刻イベント | コンテンツ力↑ | 資金極小 |
| **課金施策** | 限定ガチャ実装 | 資金↑↑↑、コンテンツ力↑、ユーザー微↓ | 資金中 |
| **課金施策** | 人権キャラ実装 | 資金↑↑↑↑、ユーザー↓ | 資金中 |
| **課金施策** | 福袋販売 | 資金↑↑ | なし |
| **課金施策** | 石バラマキ | 資金↓、ユーザー満足度↑ | なし |
| **課金施策** | 天井引き下げ | 資金微↓、ユーザー満足度↑↑ | なし |

**トラブル対応系**（強制イベント後に出現）:
- 詫び石配布（資金↓、ユーザー満足度↑）
- 公式謝罪声明（知名度回復）
- 緊急メンテ実施（技術力↑）
- 返金対応（資金↓↓↓、ユーザー満足度↑↑）

### 休養

- カードを選ばず「休養」を選択可能
- 効果: 全ステータス微増（技術力+5、知名度+5、コンテンツ力+5）
- コスト: なし
- 注意: ターンを消費するため進捗が遅れる

## 6. 強制イベントシステム

### 基本仕様

- **カード選択とは別枠で発生**（カード枠を圧迫しない）
- 毎ターン30〜50%の確率で何かしらのイベントが発生
- ポジティブ/ネガティブの比率はステータスに依存
  - 好調時: ポジティブ 70% / ネガティブ 30%
  - 普通時: ポジティブ 50% / ネガティブ 50%
  - 不調時: ポジティブ 30% / ネガティブ 70%
- 同一イベントは最低3ターンのクールダウン

### イベント連鎖

特定のイベントは連鎖・派生する:

| 起点イベント | 派生イベント | 連鎖条件 |
|---|---|---|
| サーバーダウン | メンテ延長 | 技術力が低い |
| ガチャ確率誤表記 | 返金対応 or サイレント修正 | プレイヤー選択 |
| 公式SNS失言 | まとめサイトで叩かれる | 高確率で連鎖 |
| セルラン1位 | 記念石配布カード出現 | 次ターンのカード枠 |
| 限定キャラ実装 | セルラン1位 | コンテンツ力が高い時 |
| コラボイベント | 復帰ユーザー急増 | コラボ成功時 |

### 主要イベント例

**ポジティブ**:
- セルラン1位獲得（知名度↑↑↑、ユーザー↑↑）
- 有名配信者が実況（ユーザー↑↑↑、知名度↑↑）
- 二次創作爆増（コンテンツ力↑↑、知名度↑↑）
- 攻略wiki充実（ユーザー定着率↑）
- アプリストアでフィーチャー（知名度↑↑↑、ユーザー↑↑↑）

**ネガティブ**:
- 緊急メンテナンス（そのターンのカード1枚減）
- ガチャ確率誤表記発覚（資金↓↓、知名度↓↓）
- 炎上（知名度↓↓、ユーザー↓）
- 競合タイトル登場（ユーザー↓↓、知名度↓）
- サーバーダウン（技術力↓、ユーザー↓）
- データ消失事故（ユーザー↓↓↓、資金↓↓、技術力↓↓、レア大災害）

詳細は `docs/events.md` を参照

## 8. 難易度設計

### 難易度上昇要素

1. **維持費の増加**: ターン経過で維持費が増加
   - 維持費 = 基本維持費 × (1 + ターン数 × 0.05)

2. **ユーザー離脱率の加速**: 時間経過でユーザーが離れやすくなる
   - 基本離脱率が年次で上昇

3. **知名度の減衰加速**: 経過年数で知名度の減衰が早くなる
   - 減衰係数 = 0.15 × (1 + 経過年数 × 0.1)

4. **コンテンツの陳腐化**: 時間経過でコンテンツ力が自然減衰
   - 常に新しいコンテンツを投入し続ける必要がある

5. **ネガティブイベント確率上昇**: 後半ほど災害イベントが発生しやすい
   - 競合タイトル登場などの確率上昇

6. **借金の利子**: 毎ターン発生し、借金残高に応じて増加

### バランス調整の方針

```
期待値の設計:
  序盤: 売上期待値 > 支出 → 比較的楽
  中盤: 売上期待値 ≒ 支出 → ギリギリの綱渡り
  終盤: 売上期待値 < 支出 → 戦略的な選択が必須
```

## 9. 勝利条件とエンディング

### 勝利条件

**借金完済** — 借金残高をゼロにする

### 敗北条件

以下のいずれかでゲームオーバー:
1. ユーザー数がゼロになる（サービス終了）
2. 資金がゼロになる（破産）

### エンディング

**通常エンディング**: 借金完済
- 生存期間に応じて評価ランク
  - 60ターン以上（5年）: 伝説の運営
  - 36ターン以上（3年）: 安定運営
  - 24ターン以上（2年）: まあまあ
  - 借金完済: 完済！

**真エンディング**: 借金完済 + ユーザー数50万人以上
- アニメ化決定イベント発生
- 特別なエンディング演出

**ゲームオーバー**:
- 生存期間に応じて評価
  - 12ターン未満: 即サ終
  - 12ターン以上: 短命

### 完済後

- ゲーム続行可能（フリーモード）
- 更なる目標: ユーザー数最大化、長期サービス継続など

## 11. 実装の優先順位（参考）

### Phase 1: コア実装
1. 基本ターン進行システム
2. ステータス管理
3. カード選択システム（開発期・運営期各10種程度）
4. 収支計算・ユーザー変動計算
5. 勝利/敗北判定

### Phase 2: イベント実装
1. 強制イベントシステム（プラス/マイナス各5種程度）
