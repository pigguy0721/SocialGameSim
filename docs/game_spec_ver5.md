## ■ゲーム期間

- **開発期**: 12ヶ月（12ヶ月目がリリース月）

## ■基本パラメータ

### リソース（N/C/T）

| リソース | 説明 | 用途 |
|---------|------|------|
| **知名度（N）** | マーケティング力 | 広報活動、知名度向上イベントで消費 |
| **コンテンツ（C）** | ゲーム内容の充実度 | コンテンツ制作、新規追加で消費 |
| **技術力（T）** | システム開発力 | 技術開発、バグ修正で消費 |

### ルール
- **行動コストとして消費**: 各行動・イベント対応にN/C/Tを消費
- **月初全回復**: 毎月1日にリソースが最大値まで回復
- **月末持ち越しなし**: 余ったリソースは消滅
- **最大値は成長で増加**: 行動・イベントで最大値が成長
- **初期値**: N=10, C=10, T=10

---

## ■資金

- **開発期**: 収益なし（イベントでのみ増減）
- **運営期**: 月末に収益・維持費で増減
- **敗北条件**: 資金が0未満でゲームオーバー
- **初期資金**: リリース時に5000万円を獲得

## ■隠しパラメータ（非表示）

### 流行指数（Trend）
- **内部値**: -100〜+100
- **プレイヤー非表示**: 直接の数値は表示されない
- **リリース時に決定**: `流行 = maxN + maxC + random(-20, 20)`
- **イベントで変動**: 運営期の行動・イベントで微変動

### 時間減衰（Decay）
- **月経過で減衰**: 運営期、毎月-2ずつ減少
- **流行が高いほど緩和**: 流行指数が高いと減衰が遅い
- **プレイヤー非表示**: 内部パラメータ

### 勢い（Momentum）
- **収益計算に使用**: `(maxN + maxC) × 流行補正 × 時間減衰`
- **非表示**: プレイヤーには見えない

## ■プレイヤーに見える形

### ストア評価
- **表示**: ★1〜★5
- **判定基準**: 流行指数に基づく
  - ★5: trend >= 60
  - ★4: trend >= 30
  - ★3: trend >= 0
  - ★2: trend >= -30
  - ★1: trend < -30

### 状況コメント（運営期のみ）
流行指数に応じたラベル表示:
- **trend >= 60**: 「SNSで話題」
- **trend >= 30**: 「堅調」
- **trend >= 0**: 「安定」
- **trend >= -30**: 「新規流入が鈍化」
- **trend < -30**: 「やや過疎」

## ■月進行

### 月初（processMonthStart）
1. **リソース全回復**: N/C/Tが最大値まで回復
2. **行動回数リセット**: `actionsRemaining = 4`
3. **当月イベント生成**: 4件のイベントを生成（プラス/マイナス混在）
4. **未来イベント予告**: 3ヶ月先まで表示（来月、2ヶ月後、3ヶ月後）

### 行動フェーズ
- **行動回数**: 月4回
- **選択肢**:
  - 通常行動（5種類: 広報、コンテンツ、技術、アイテム調達、何もしない）
  - イベント対応（最大4件）
  - アイテム使用（行動消費なし、何回でも可）

### 月末（processMonthEnd）
1. **未対応マイナスイベントのペナルティ**: 1件あたり-100万円
2. **収益計算**（運営期のみ）:
   - 収益 = `(maxN + maxC) × 10 + trend × 5`
   - 維持費 = 200万円（固定）
3. **流行減衰**（運営期のみ）: `trend -= 2`
4. **ストア評価更新**（運営期のみ）

## ■フェーズ

### 開発期（1〜11ヶ月）
- **収益**: なし
- **セルラン**: なし
- **アイテム蓄積**: 可能
- **成長**: リソース上限を伸ばす期間

### 12ヶ月目（リリース月）
- **通常行動**: 可能（月4回）
- **月末処理**:
  - 初期流行確定: `trend = maxN + maxC + random(-20, 20)`
  - 初期資金獲得: 5000万円
- **次月から運営期**: 13ヶ月目以降

### 運営期（13〜48ヶ月）
- **収益発生**: 毎月末に収益・維持費計算
- **流行微変動**: 行動・イベントで変化
- **減衰進行**: 毎月-2ずつ減少
- **サ終判定**: 資金 < 0でゲームオーバー

### 開発期の行動（devActions）

| 行動名 | コスト | 効果 | 説明 |
|--------|--------|------|------|
| **広報活動** | N:5 | maxN +2 | SNSやメディアで宣伝 |
| **コンテンツ制作** | C:5 | maxC +2 | ゲーム内容を充実させる |

## ■イベントシステム

### 概要
- **発生数**: 月4件
- **種類**: プラスイベント、マイナスイベント
- **対応**: N/C/Tを消費して対応
- **未対応ペナルティ**: マイナスイベントを放置すると月末に-100万円

### イベントの種類

#### 開発期プラスイベント（3件）
1. **優秀な人材応募**: コストN:5 → maxN+4, maxC+2
2. **協力企業からの支援**: コストC:3,T:3 → maxT+6, money+300
3. **技術ブレイクスルー**: コストT:8 → maxT+10, maxC+4

#### 開発期マイナスイベント（2件）
1. **主要スタッフ退職**: コストN:3,C:3,T:3 → 全リソース+2（引き留め成功）
2. **開発機材トラブル**: コストT:5 → maxT+4（復旧完了）

#### 運営期プラスイベント（4件）
1. **バズる投稿**: コストN:8 → trend+30, money+400
2. **配信者が紹介**: コストN:5,C:5 → trend+20, maxN+6
3. **アワード受賞**: コストN:6,C:6 → trend+40, maxN+8, money+600
4. **大型アップデート成功**: コストC:8,T:5 → trend+24, maxC+6, money+500

#### 運営期マイナスイベント（5件）
1. **重大バグ発生**: コストT:10 → maxT+8, trend+10（迅速対応で信頼回復）
2. **炎上騒動**: コストN:10 → maxN+6, trend+6（鎮火成功）
3. **サーバーダウン**: コストT:8 → maxT+10, money+200（補償）
4. **ライバルゲーム登場**: コストN:8,C:8 → trend+16, maxN+4, maxC+4（差別化成功）
5. **虚無期間**: コストC:10 → maxC+10, trend+12（緊急イベント投入）

## ■収益システム（運営期のみ）

### 概念式
```
収益 = 勢い × 課金率
勢い = (maxN + maxC) × 流行補正 × 時間減衰
```

### 実装式（簡易版）
```
月間収益 = (maxN + maxC) × 10 + trend × 5
月間維持費 = 200万円（固定）
純利益 = 月間収益 - 維持費
```

**例**: maxN=40, maxC=35, trend=50の場合
- 収益: (40 + 35) × 10 + 50 × 5 = 750 + 250 = 1000万円
- 純利益: 1000 - 200 = 800万円
