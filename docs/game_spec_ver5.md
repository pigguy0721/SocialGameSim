# ソシャゲ運営シミュレーション仕様 v5.8（フェーズ＋流行システム）

**最終更新**: 2026-02-09
**バージョン**: v5.8

---

## ■ゲーム期間

- **開発期**: 12ヶ月（12ヶ月目がリリース月）
- **運営期**: 36ヶ月
- **合計**: 48ヶ月

**勝利条件**: 48ヶ月完走
**敗北条件**: 運営期に資金が0未満でサービス終了

---

## ■基本パラメータ

### リソース（N/C/T）

| リソース | 説明 | 用途 |
|---------|------|------|
| **知名度（N）** | マーケティング力 | 広報活動、知名度向上イベントで消費 |
| **コンテンツ（C）** | ゲーム内容の充実度 | コンテンツ制作、新規追加で消費 |
| **技術力（T）** | システム開発力 | 技術開発、バグ修正で消費 |

### ルール
- **行動コストとして消費**: 各行動・イベント対応にN/C/Tを消費
- **月初全回復**: 毎月1日にリソースが最大値まで回復
- **月末持ち越しなし**: 余ったリソースは消滅
- **最大値は成長で増加**: 行動・イベントで最大値が成長
- **初期値**: N=10, C=10, T=10

## ■資金

- **開発期**: 初期借金-2000万円、収益なし（イベントでのみ増減）
- **運営期**: 月末に収益・維持費で増減
- **敗北条件**: 資金が0未満でゲームオーバー
- **初期資金**: リリース時に5000万円を獲得（借金返済に使える）

## ■隠しパラメータ（非表示）

### 流行指数（Trend）
- **内部値**: -100〜+100
- **プレイヤー非表示**: 直接の数値は表示されない
- **リリース時に決定**: `流行 = maxN + maxC + random(-20, 20)`
- **イベントで変動**: 運営期の行動・イベントで微変動
- **減衰設定**: デフォルト-2/月（設定画面で変更可能）

### 時間減衰（Decay）
- **月経過で減衰**: 運営期、毎月設定値ずつ減少
- **流行が高いほど緩和**: 流行指数が高いと減衰が遅い
- **プレイヤー非表示**: 内部パラメータ

## ■プレイヤーに見える形

### ストア評価
- **表示**: ★1〜★5
- **判定基準**: 流行指数に基づく
  - ★5: trend >= 60
  - ★4: trend >= 30
  - ★3: trend >= 0
  - ★2: trend >= -30
  - ★1: trend < -30

### セルランキング（v5.4追加）
- **表示**: 1位〜50位+
- **計算式**: `rankScore = trend + storeRating × 10`
- **範囲**: 1位〜50位（50位以下は「50位+」表示）
- **運営期のみ表示**

### 状況コメント（運営期のみ）
流行指数に応じたラベル表示:
- **trend >= 60**: 「SNSで話題」
- **trend >= 30**: 「堅調」
- **trend >= 0**: 「安定」
- **trend >= -30**: 「新規流入が鈍化」
- **trend < -30**: 「やや過疎」

## ■月進行

### 月初（processMonthStart）
1. **リソース全回復**: N/C/Tが最大値まで回復
2. **行動回数リセット**: `actionsRemaining = 4`
3. **当月イベント生成**: 4件のイベントを生成（プラス/マイナス混在）
4. **未来イベント予告**: 3ヶ月先まで表示（来月、2ヶ月後、3ヶ月後）
5. **選択位置リセット**: カーソル位置を1番にリセット

### 行動フェーズ
- **行動回数**: 月4回
- **選択肢**:
  - 通常行動（6種類: 広報、コンテンツ、技術、コンテンツ実装、ガチャ実装、何もしない）
  - イベント対応（最大4件）
  - アイテム使用（行動消費なし、何回でも可）

### 月末（processMonthEnd）
1. **未対応マイナスイベントのペナルティ**: 1件あたり-100万円
2. **恒常収益加算**（運営期のみ、v5.6追加）:
   - 恒常コンテンツ・恒常ガチャからの毎月収益
3. **維持費**（運営期のみ）: -200万円（固定）
4. **流行減衰**（運営期のみ）: 設定値（デフォルト-2）
5. **ストア評価・セルラン更新**（運営期のみ）
6. **目標達成判定**（v5.4追加）

## ■フェーズ

### 開発期（1〜11ヶ月）
- **収益**: なし
- **維持費**: なし
- **セルラン**: なし
- **アイテム蓄積**: 可能
- **成長**: リソース上限を伸ばす期間

### 12ヶ月目（リリース月）
- **通常行動**: 可能（月4回）
- **月末処理**:
  - 基本流行確定: `trend = maxN + maxC + random(-20, 20)`
  - 恒常アイテム補正（v5.8）: `trend += (恒常コンテンツ数 + 恒常ガチャ数) × 3`
  - 初期資金獲得: 5000万円
- **次月から運営期**: 13ヶ月目以降
- **開発期の恒常アイテムが有利**: 多く実装するほどリリース時の流行値が高くなる

### 運営期（13〜48ヶ月）
- **収益発生**: 恒常収益（毎月末）、限定収益（アイテム使用時）
- **維持費**: 200万円/月
- **流行微変動**: 行動・イベントで変化
- **減衰進行**: 毎月設定値ずつ減少
- **サ終判定**: 資金 < 0でゲームオーバー

## ■収益システム（v5.6で完全再設計）

### 概要
- **旧システム削除**: 月次自動収益を廃止
- **新システム**: 4種類のアイテムのみから収益発生

### 収益アイテム（4種類）

#### 1. 恒常コンテンツ
- **収益**: 30-60万円/月（恒常収益）
- **流行**: +3～8
- **特徴**: 安定した収益基盤

#### 2. 限定コンテンツ
- **収益**: 300-600万円（一時）
- **流行**: +15～30
- **特徴**: 大型収益、流行値への影響大

#### 3. 恒常ガチャ
- **収益**: 40-80万円/月 ±30%（恒常収益・変動あり）
- **流行**: +5～12
- **特徴**: 安定収益だが変動リスクあり

#### 4. 限定ガチャ
- **収益**: 500-1000万円 ±40%（一時・大きく変動）
- **流行**: -20～-10（マイナス効果）
- **特徴**: ハイリスクハイリターン

### 収益の仕組み

#### 恒常収益
- 恒常コンテンツ・恒常ガチャは月末に自動収益
- `state.recurringRevenue` に累積
- 毎月末に `money += recurringRevenue`

#### 限定収益
- 限定コンテンツ・限定ガチャは使用時に即時収益
- 一回限りの大型収益

#### 維持費
- 開発期: 0万円/月
- 運営期: 200万円/月

## ■アイテムシステム

### 概要
- **使用コスト**: なし
- **行動消費**: なし（何回でも使用可能）
- **所持上限**: なし（無制限）
- **性能**: ランダム（テンプレートから生成）
- **UI**: 右カラムにスクロール表示（v5.7）

### 使用制限（v5.8追加）
#### 開発期（1〜12ヶ月）
- **恒常コンテンツ・恒常ガチャ**: 使用可能
  - 収益効果なし（運営期に入ると収益発生開始）
  - リリース時の補正に影響（恒常アイテム数が多いほど初期流行値にボーナス）
- **限定コンテンツ・限定ガチャ**: 使用不可
  - 開発期は実装できない（運営期まで保持）

#### 運営期（13〜48ヶ月）
- **全アイテム使用可能**: 制限なし

### アイテムの種類
アイテムは実際のソシャゲ運営で行う「施策」として実装されています。

#### 開発期専用施策（7種類）
1. **βテスト実施**: 技術+5～10, コンテンツ+3～5
2. **事前登録キャンペーン**: 知名度+8～15
3. **PV制作**: 知名度+6～12, コンテンツ+2～4
4. **インフルエンサー契約**: 知名度+10～18
5. **ボイス収録**: コンテンツ+8～15
6. **クラウドファンディング**: 資金+200～600万, 知名度+3～6
7. **ストアページ最適化**: 知名度+4～8

#### 運営期専用施策（8種類）
1. **TV広告出稿**: 知名度+10～20, 流行+5～12, 資金-300～-500万（コスト）
2. **Web広告キャンペーン**: 知名度+5～10, 流行+3～8, 資金-100～-200万（コスト）
3. **リアルイベント開催**: 知名度+8～15, 流行+10～18, 資金-200～-400万（コスト）
4. **インフルエンサー案件**: 知名度+6～12, 流行+8～15
5. **バグ修正大会**: 技術+5～12, 流行+3～8
6. **ガチャ天井実装**: 流行+10～20, 技術+3～6, 資金-50～-150万
7. **レイドボス追加**: コンテンツ+4～8, 技術+2～5, 流行+6～12
8. **コラボイベント**: 流行+15～25, 知名度+3～8, 資金+100～300万

#### 両フェーズ共通施策（4種類）
1. **資金調達**: 資金+100～500万
2. **スタッフ増員**: 全リソース+2～5
3. **技術基盤強化**: 技術+5～12
4. **外注リソース**: コンテンツ+5～10, 資金-100～-300万

#### 収益アイテム（運営期、v5.6追加）

2. **限定コンテンツ**: 300-600万（一時）, 流行+15～30
3. **恒常ガチャ**: 40-80万/月±30%, 流行+5～12
4. **限定ガチャ**: 500-1000万±40%（一時）, 流行-20～-10

## ■イベントシステム

### 概要
- **発生数**: 月4件
- **種類**: プラスイベント、マイナスイベント
- **対応**: N/C/Tを消費して対応
- **未対応ペナルティ**: マイナスイベントを放置すると月末に-100万円

### イベントの種類

#### 開発期プラスイベント（3件）
1. **優秀な人材応募**: コストN:5 → maxN+4, maxC+2
2. **協力企業からの支援**: コストC:3,T:3 → maxT+6
3. **技術ブレイクスルー**: コストT:8 → maxT+10, maxC+4

#### 開発期マイナスイベント（2件）
1. **主要スタッフ退職**: コストN:3,C:3,T:3 → 全リソース+2（引き留め成功）
2. **開発機材トラブル**: コストT:5 → maxT+4（復旧完了）

#### 運営期プラスイベント（4件）
1. **バズる投稿**: コストN:8 → trend+30
2. **配信者が紹介**: コストN:5,C:5 → trend+20, maxN+6
3. **アワード受賞**: コストN:6,C:6 → trend+40, maxN+8
4. **大型アップデート成功**: コストC:8,T:5 → trend+24, maxC+6

#### 運営期マイナスイベント（5件）
1. **重大バグ発生**: コストT:10 → maxT+8, trend+10（迅速対応で信頼回復）
2. **炎上騒動**: コストN:10 → maxN+6, trend+6（鎮火成功）
3. **サーバーダウン**: コストT:8 → maxT+10（迅速復旧）
4. **ライバルゲーム登場**: コストN:8,C:8 → trend+16, maxN+4, maxC+4（差別化成功）
5. **虚無期間**: コストC:10 → maxC+10, trend+12（緊急イベント投入）

**注**: v5.3で全イベントの効果が2倍に調整されました
