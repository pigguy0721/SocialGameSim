# ソシャゲ運営ローグライク ブレインストーミング

## 1. ゲーム全体の流れ：借金返済 + 2フェーズ制

### コンセプト

プレイヤーは借金をしてソシャゲを開発・リリースし、運営で借金を返済する。
「借金完済」という明確なゴールがあることで、目標が分かりやすくなる。

### フェーズ構成

```
【フェーズ1: 開発期（リリース前）】 約24ターン（2年間）
  借金で資金を調達 → ゲームの土台を作る
      ↓
【リリース判定】 ステータスが一定以上ならリリース可能
      ↓
【フェーズ2: 運営期（リリース後）】 借金返済＋サービス継続
  売上で借金を返しながらサ終を回避
      ↓
【エンディング】 借金完済 or サービス終了
```

### フェーズ1: 開発期

- 期間: 24ターン（2年）。毎ターン借金の利子が発生
- 初期借金額: 3000万〜5000万（選択式 or 固定）
- 収入はゼロ。借金を切り崩しながらゲームを作る
- カードの内容は開発系（コンテンツ制作、技術基盤構築、プロモーション先行投資など）
- リリース時のステータスが運営期の初期状態になるため、何に投資するかの戦略性がある
- 開発期中に追加融資（借金増額）も可能にする？→ ハイリスク・ハイリターン

#### 開発期カード案

| カード名 | 効果 | 備考 |
|---|---|---|
| キャラデザイン発注 | コンテンツ力↑ | 基本投資 |
| シナリオ執筆 | コンテンツ力↑↑、マンネリ耐性↑ | 長期的に効く |
| サーバー基盤構築 | 技術力↑↑ | 運営期の安定に直結 |
| ティザーサイト公開 | 話題性↑ | リリース前のブースト |
| 事前登録キャンペーン | 話題性↑↑、初期ユーザー↑ | リリース時ユーザー数に影響 |
| 有名声優起用 | 話題性↑↑、コスト大 | 豪華路線 |
| βテスト実施 | 技術力↑、コンテンツ力を微調整 | バグを事前に潰せる |
| マーケティング調査 | 次ターンのカードの質向上？ | メタ的な効果 |

#### リリース判定

- 開発期終了時（24ターン目）に自動でリリースされる
- ただし一定以上のステータスがないと「低評価スタート」になりペナルティ
- 例: コンテンツ力30以上 & 技術力20以上 で「普通のリリース」、それ以下だと初期ユーザー激減

### フェーズ2: 運営期（現行ゲームの拡張）

- 借金残高が表示される。毎ターン利子も発生
- 売上の一部が自動的に返済に回る（返済比率を設定できても面白い）
- **勝利条件: 借金完済**（サ終せずに返し切る）
- 完済後もプレイ続行可能（フリーモード / 更なる目標）

## 2. マイルストーン（中間目標）

借金返済だけだと道中が単調になるので、マイルストーンで達成感を与える。

### マイルストーン案

| マイルストーン | 条件 | 報酬・効果 |
|---|---|---|
| 事前登録1万人突破 | 開発期で話題性を一定以上に | リリース時の初期ユーザーにボーナス |
| リリース成功 | フェーズ1完了 | 運営期突入 |
| ユーザー1万人 | ユーザー数到達 | 特別カード解放 or 話題性ブースト |
| ユーザー10万人 | ユーザー数到達 | メディア露出イベント発生 |
| 初月黒字達成 | 月の売上 > 維持費 | 投資家からの追加支援（借金利子軽減？） |
| ハーフアニバーサリー | 運営6ヶ月到達 | 記念イベントカード出現 |
| 借金半額返済 | 借金残高が初期の50%以下 | 精神的余裕で体力回復↑ |
| 1周年 | 運営12ヶ月到達 | アニバ記念カード、ユーザー流入ブースト |
| 借金完済 | 残高ゼロ | エンディング＋評価 |
| アニメ化決定 | 完済後 + ユーザー数一定以上 | 真エンディング？ |

### 表示方法

- 画面上部にプログレスバーとして次のマイルストーンまでの進捗を表示
- 達成時に演出（画面フラッシュ + テキスト表示）

## 3. ステータス項目の再設計

カイロソフト的な「現実のパラメータを可視化して楽しむ」方向。
項目を増やして、ソシャゲ運営の「あるある」をプレイヤーが体験できるようにする。

### 現行ステータス

- ユーザー数、資金、体力、コンテンツ力、技術力、話題性、課金圧

### 追加候補ステータス

| パラメータ | 説明 | ゲーム的な役割 |
|---|---|---|
| **マンネリ度** | コンテンツの新鮮さの欠如 | 時間経過で自然上昇。高いとユーザー離脱率↑。新コンテンツ追加で下がる |
| **ファン熱量** | コアファンの熱心さ | 高いと課金率↑、口コミ流入↑。炎上で激減 |
| **開発チーム士気** | 体力の代わり or 体力を補完 | 低いとカード効果減少。休養・ボーナス支給で回復 |
| **バグ数（技術的負債）** | 蓄積されたバグ | 時間経過・機能追加で増加。放置するとサーバーダウン確率↑ |
| **ブランド力** | 長期的な信頼 | ゆっくり上がり、ゆっくり下がる。高いとユーザー復帰率↑ |
| **競合プレッシャー** | 市場の競争激しさ | 時間経過で上昇。高いとユーザー獲得コスト↑ |
| **借金残高** | 返済すべき金額 | メインの勝利条件に直結 |
| **世間の注目度** | 話題性と別軸の「メディア露出」 | 広告・コラボで上がる。ユーザー獲得の乗算係数 |

### ステータスの取捨選択の方針

- 画面に常時表示するのは6〜8項目が限界（UIの都合）
- 「プレイヤーが直感的にわかる現実のソシャゲ指標」を優先
- 内部パラメータとして持つが表示しないものがあってもよい

### 推奨する構成（暫定）

**常時表示（メイン）:**
- ユーザー数、資金（借金残高）、コンテンツ力、技術力、話題性、マンネリ度

**サブ表示 or ツールチップ:**
- ファン熱量、課金圧、バグ数、開発チーム士気

## 4. 強制イベントの再設計

現行: 災害カードが手札3枚に混ざる → カード選択と競合してしまう

### 改善案: 強制イベントをカード選択とは別枠にする

```
ターン開始
  ↓
【強制イベント判定】→ 発生したら演出表示（スキップ不可）
  ↓
【カード選択】→ 通常通り3枚から選ぶ（災害カードは混ざらない）
```

### 強制イベントの種類（プラス・マイナス両方）

#### ポジティブ強制イベント

| イベント名 | 効果 | 発生条件案 |
|---|---|---|
| バズった！ | 話題性↑↑、ユーザー↑↑ | 話題性が高い時にランダム |
| 有名配信者がプレイ | ユーザー↑、話題性↑ | ランダム |
| アプリストアでフィーチャー | ユーザー↑↑↑ | コンテンツ力が高い時 |
| ファンが二次創作で盛り上がる | ファン熱量↑、話題性↑ | コンテンツ力 + 話題性が一定以上 |
| 投資家から追加出資の申し出 | 資金↑（借金ではない） | 業績好調時 |
| 神アプデが刺さった | マンネリ度大幅↓ | 直前にコンテンツ系カード使用後 |

#### ネガティブ強制イベント

| イベント名 | 効果 | 発生条件案 |
|---|---|---|
| 大規模バグ発生 | 技術力↓、ユーザー↓ | 技術力が低い時に確率↑ |
| 炎上 | 話題性↓、ファン熱量↓ | 課金圧が高い時に確率↑ |
| 競合タイトル登場 | ユーザー↓、話題性↓ | ランダム（後半ほど確率↑） |
| サーバーダウン | ユーザー↓、資金↓ | 技術力低い or バグ数多い時 |
| 主要スタッフ退職 | 士気↓、次ターンのカード効果↓ | 士気が低い時 |
| ガチャ確率問題で炎上 | 課金圧↓、ユーザー↓ | 課金圧が非常に高い時 |
| まとめサイトに晒される | 話題性は上がるがファン熱量↓ | 炎上系の派生 |

### 強制イベントの発生確率

- 毎ターン30〜50%で何かしらのイベントが発生
- ポジティブ/ネガティブの比率はステータスに依存
  - 運営状態が良い → ポジティブ寄り
  - 運営状態が悪い → ネガティブ寄り（悪循環の表現）
- 同じイベントは短期間で連続しない（クールダウン）

## 5. 成功率の撤廃と大成功システム

### 現行の問題

- プレイヤーが能動的に選んだアクションが「失敗」するのはストレス
- 体力コストを払っているのに失敗は二重のペナルティ感

### 改善案

- **通常のカード実行は100%成功**（選んだ行動は必ず実行される）
- **大成功判定を追加**（ボーナス効果が乗る）
  - 大成功率はステータスに依存（例: 関連ステータスが高いと大成功しやすい）
  - 大成功時は効果が1.5倍〜2倍
  - 演出で気持ちよさを出す

### 大成功の条件案

| カード系統 | 大成功条件 | 大成功率目安 |
|---|---|---|
| コンテンツ系 | コンテンツ力が高い | 10〜30% |
| 技術系 | 技術力が高い | 10〜30% |
| 広報・話題系 | 話題性が高い | 10〜30% |
| 課金系 | ユーザー数が多い | 10〜30% |

## 6. カイロソフト的な「モチーフを楽しむ」要素

### 核心: 「自分だったらこうするのに」を体験できること

- プレイヤーの選択がちゃんと結果に反映される手触り
- 「コンテンツに投資したらユーザーが増えた」「課金圧上げすぎたら炎上した」が直感的

### 演出・フレーバー案

| 要素 | 内容 |
|---|---|
| SNS風フィード | ターン結果をTwitter/X風の投稿で表示（「神アプデきた！」「サ終しそう…」） |
| レビュースコア | アプリストア風の星評価（コンテンツ力・課金圧・バグ数から算出） |
| トレンドランキング | 話題性に応じた順位表示（「今月のトレンド3位！」） |
| 開発室の様子 | 士気やバグ数に応じた一枚絵 or テキスト描写 |
| ユーザーの声 | ステータスに応じたランダムなユーザーコメント表示 |
| 売上グラフ | 過去数ヶ月の売上推移をミニグラフ表示 |
| ニュース速報 | 強制イベント発生時に「速報」風の演出 |

### ユーザーの声の例

```
コンテンツ力高い時:
  「このゲームのストーリーマジで神」「新キャラかわいすぎ」

課金圧高い時:
  「またガチャ更新かよ…」「無課金に人権ないゲーム」

マンネリ度高い時:
  「最近イベント同じようなのばっかり」「飽きてきた」

技術力低い時:
  「また落ちたんだけど」「ロード長すぎ」
```

## 7. バランス調整方針：期待値計算

### 基本方針

- 各カードの効果を期待値で管理し、数値設計を一元化する
- 「1ターンで得られるリソースの期待値」と「1ターンで失われるリソースの期待値」の比率でバランスを取る

### バランスの軸

```
月間売上の期待値 > 月間コスト（維持費 + 借金利子）

これを序盤は楽に、中盤でギリギリ、終盤で厳しくなるように曲線を設計
```

### 調整パラメータ

- 借金の総額と利子率
- 維持費の上昇カーブ
- ユーザー離脱率の上昇カーブ
- マンネリ度の上昇速度
- カード効果の数値レンジ
- 強制イベントの発生確率とプラス/マイナスの比率

## 8. 未整理のアイデア・検討事項

- 周回要素: 1回クリア（借金完済）後にアンロックされる要素？（高難度モード、新カード）
- 開発期で選べるゲームジャンル（RPG / パズル / アクション）で運営期のパラメータ傾向が変わる？
- スタッフ雇用要素: カードではなく常駐効果を持つスタッフをリソースで雇う
- シーズンパス / バトルパス実装のような「現代ソシャゲあるある」カード
- 「メンテナンス延長」のようなフレーバー豊かな災害イベント
- リリース前に借金額を自分で決められると戦略性が出る（多く借りる＝開発リッチだが返済キツい）
